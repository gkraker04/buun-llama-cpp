## What This Proves

1. **RPC server binary builds successfully** — `rpc-server.exe` is produced when `-DGGML_RPC=ON` is added to cmake
2. **RPC protocol works over localhost** — llama-server connects to rpc-server via TCP and performs inference
3. **Model loading works** — 27B Q4_K_M model loads successfully over RPC
4. **Inference works** — Correct output generated via RPC backend
5. **GPU offload works** — All layers offloaded to GPU via RPC

---

## Notes

- Both servers run on the same machine (localhost), but use the full RPC protocol over TCP
- This tests correctness, not performance (localhost has minimal latency)
- The RPC backend serializes tensors and sends them over TCP, then receives results
- This is the foundation for distributed inference over WAN

## Next Steps

**T1.1 — Implement SYNC command**
- Add `RPC_CMD_SYNC` to the wire protocol
- Implement `ggml_backend_rpc_synchronize()` to send SYNC and wait for response
- This enables the scheduler to know when RPC operations complete

**T1.2 — Implement event functions**
- Add `RPC_CMD_EVENT_NEW`, `RPC_CMD_EVENT_FREE`, `RPC_CMD_EVENT_RECORD`, `RPC_CMD_EVENT_WAIT`
- Implement device interface functions: `.event_new`, `.event_free`, `.event_record`, `.event_wait`
- This enables the scheduler to use events for pipeline parallelism

**T1.3 — Enable async caps**
- Set `caps.async = true` and `caps.events = true` in backend capabilities
- This tells the scheduler that RPC backend supports async operations
- Enables pipeline parallelism code path
